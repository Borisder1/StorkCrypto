# Відновлення канонічного LoadingScreen за Маніфестом Проєкту

Цей план приводить екран завантаження `LoadingScreen.tsx` у строгу 100% відповідність до правил `PROJECT_MANIFESTO.md` та початкової архітектури `Loading.txt`, повертаючи вертикальне розташування літер та сканування зверху вниз, а також видаляючи зайві сторонні нашарування.

## Підтверджені рішення користувача

> [!IMPORTANT]
> На основі відповідей на уточнюючі питання зафіксовано такі непорушні параметри:

- **Орієнтація та сканування**: Вертикальна колонка літер `S T O R K C R Y P T O` з рухом горизонтальної лазерної лінії зверху вниз (0.0–2.5с).
- **Склад візуальних шарів**: Суворо канонічний набір з маніфесту (кібер-сітка, 3D-літери з шифром `CIPHER_POOL`, лазерний сканер, канвас із частинками кібер-енергії, прогрес-бар з відсотками та 8 стадіями телеметрії ядра).
- **Вилучення зайвих елементів**: Повне видалення концентричних обертових кілець, туманних радіальних оверлеїв та фінальної емблеми монети, які не передбачені маніфестом.

---

## 1. Огляд та ціль відновлення

- **Що робить екран завантаження**: Забезпечує обов'язкову 6.5-секундну атмосферну ініціалізацію нейромережі StorkCrypto ("Neural Sync"), готуючи мобільний клієнт Telegram Mini App та PWA до відображення терміналу.
- **Відповідність маніфесту**:
  - `STATUS: IMMUTABLE` (заборона видалення або скорочення 6.5с).
  - Таймінг: 2.5с сканування + 3.2с зарядка нейромережі + 0.8с фіналізація переходу.
  - Жодних статичних знаків `?`: контрольована динамічна генерація з `CIPHER_POOL` на зворотних гранях 3D-кубів літер.
  - 8 канонічних стадій телеметрії над прогрес-баром.

### Фази анімації (Строго 6.5с):
1. **Фаза 1 (0.0с – 2.5с) — Лазерне 3D-сканування зверху вниз**:
   - Текст `STORKCRYPTO` розташований у вертикальній колонці по центру.
   - Горизонтальна неонова лінія шириною 300px рухається зверху вниз (`translateY`).
   - Кожна літера плавно розкривається через 3D-переворот `rotateX(-90deg) -> rotateX(0deg)` при проходженні сканера.
   - Нерозкриті грані відображають живий крипто-перебір `CIPHER_POOL`.
2. **Фаза 2 (2.5с – 6.0с) — Передача енергії до прогрес-бару**:
   - Сканер плавно зникає (fade out 0.3c).
   - Літери переходять у режим пульсації `cyberPulse` (`draining`).
   - Частинки `EnergyParticle` генеруються від вертикального блоку літер та летять вниз у прогрес-бар.
   - Прогрес-бар заповнюється 0% -> 100% з синхронною зміною статусу телеметрії.
3. **Фаза 3 (6.0с – 6.5с) — Фіналізація**:
   - Досягнення 100%, статус `SYSTEM READY // CONNECTED`.
   - Тактильний відгук `triggerHaptic('success')`.
   - Плавний перехід у головний екран терміналу.

## 3. Ключові зміни в коді `components/LoadingScreen.tsx`

| Елемент | Було (після попередніх правок) | Стане (за Маніфестом) |
| :--- | :--- | :--- |
| **Орієнтація контейнера літер** | `flex-row flex-nowrap` (горизонтальний рядок) | `flex-col items-center` (вертикальна колонка) |
| **Рух сканера** | `translateX` (зліва направо) | `translateY` (зверху вниз, `left: 50%`, `translateX(-50%)`) |
| **Розмір літер** | `clamp(16px, 4.8vw, 28px)` | `clamp(20px, 4.5vh, 32px)` з відступами `clamp(0px, 0.1vh, 2px) 0` |
| **Концентричні кільця** | Присутні 3 обертові SVG/div кола | **Вилучено повністю** |
| **Радіальний кібер-туман** | Присутній div фону | **Вилучено повністю** |
| **Фінальна емблема монети** | Присутня при 100% | **Вилучено повністю** |
| **Фонова сітка** | 40px | 50px `gridMove` як у канонічному `Loading.txt` |
| **Ширина сканера** | 3px вертикальна лінія | 300px горизонтальна лінія з градієнтом `#00d9ff` |

## 4. План реалізації та перевірки

1. **Редагування `components/LoadingScreen.tsx`**:
   - Відновити вертикальну геометрію та обчислення координат сканування за віссю Y (`currentY >= letterRect.top`).
   - Оновити CSS-класи для контейнера літер, сканера та фонової сітки відповідно до `Loading.txt` та `PROJECT_MANIFESTO.md`.
   - Зберегти перевірений `CIPHER_POOL` та 8 стадій статусу ядра.
   - Видалити концентричні кільця, туман та блокчейн-монету.
2. **Перевірка компіляції та тестів**:
   - Запуск `compile_applet` для верифікації відсутності TypeScript/JSX помилок.
   - Запуск `npm run test:stars` та `npm run test:security` для підтвердження відсутності регресій.
